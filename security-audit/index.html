4. Deep-Dive Vulnerability Analyses & Remediations

SEC-CRIT-01 Zip-Slip Arbitrary File Overwrite & RCE in Decryption Script
Critical · CVSS 9.8 Remediated
Affected File: tools/decrypt.ps1:115-132 CWE: CWE-22 (Improper Limitation of a Pathname)

In tools/decrypt.ps1, archive entries were extracted via Path.Combine(targetFolder, entry.FullName). In .NET Framework, Path.Combine resolves ../ relative traversal sequences, and ignores targetFolder entirely if entry.FullName is rooted (e.g. C:\Windows\...). A crafted .zev container could write files to Startup directories without user interaction.

C# / PowerShell Containment Enforcement (`tools/decrypt.ps1`) 
string targetFullPath = Path.GetFullPath(targetFolder);
if (!targetFullPath.EndsWith(Path.DirectorySeparatorChar.ToString()))
    targetFullPath += Path.DirectorySeparatorChar;

foreach (var entry in archive.Entries) {
    string cleanName = entry.FullName.Replace('\\', '/').TrimStart('/');
    string destPath = Path.GetFullPath(Path.Combine(targetFolder, cleanName));
    if (!destPath.StartsWith(targetFullPath, StringComparison.OrdinalIgnoreCase))
        throw new System.Security.SecurityException("Zip-Slip detected: " + entry.FullName);

    // Enforce Windows reserved device name validation
    string fileNameOnly = Path.GetFileName(cleanName);
    if (Regex.IsMatch(fileNameOnly, @"^(CON|PRN|AUX|NUL|COM[1-9]|LPT[1-9])(\..*)?$", RegexOptions.IgnoreCase))
        throw new System.Security.SecurityException("Reserved device name: " + entry.FullName);
}
SEC-CRIT-02 CreditFlowController & OrderedReassemblyQueue Deadlock on Abort
Critical · CVSS 7.5 Remediated
Affected File: js/worker-bridge.js:76-148, 848-937 CWE: CWE-833 (Deadlock) / CWE-404 (Resource Management)

When processing large vaults, credits are exhausted under backpressure. When an operation aborted or experienced an I/O error, workers terminated without releasing credits, causing pending promises in flowController.waiters and reassemblyQueue.drainWaiters to hang indefinitely.

JavaScript Fail-Closed Abort Protocol (`js/worker-bridge.js`) 
CreditFlowController.prototype.abort = function(reason = new Error('Flow controller aborted')) {
    this.isAborted = true;
    this.abortReason = reason;
    while (this.waiters.length > 0) {
        const waiter = this.waiters.shift();
        try { if (waiter && typeof waiter.reject === 'function') waiter.reject(reason); } catch (_) {}
    }
};

OrderedReassemblyQueue.prototype.abort = function(reason = new Error('Reassembly queue aborted')) {
    this.hasError = true;
    this.abortReason = reason;
    for (const [, item] of this.buffer.entries()) {
        if (item && item.plainChunk && typeof item.plainChunk.fill === 'function') item.plainChunk.fill(0);
    }
    this.buffer.clear();
    while (this.drainWaiters.length > 0) {
        const waiter = this.drainWaiters.shift();
        try { if (waiter && typeof waiter.reject === 'function') waiter.reject(reason); } catch (_) {}
    }
};

SEC-HIGH-04 Cryptographic Precursor Keys Lingering in Memory
High · CVSS 6.2 Remediated
Affected File: js/stream-crypto.js:128-177 CWE: CWE-316 (Cleartext Storage of Sensitive Information in Memory)

In deriveMasterKey, intermediate Uint8Array buffers (passwordBytes, rawKeyBytes, mixedKey, keyfileHash) remained in JS heap memory after key derivation, violating zero-knowledge memory safety.

Guaranteed Zeroization via try...finally (`js/stream-crypto.js`) 
try {
    keyMaterial = await subtle.importKey('raw', passwordBytes, { name: 'PBKDF2' }, false, ['deriveBits']);
    const derivedBits = await subtle.deriveBits({ name: 'PBKDF2', salt, iterations, hash: 'SHA-512' }, keyMaterial, 256);
    rawKeyBytes = new Uint8Array(derivedBits);
    // ... optional keyfile XOR mixing ...
    return await subtle.importKey('raw', rawKeyBytes, { name: 'AES-GCM', length: 256 }, false, ['encrypt', 'decrypt']);
} finally {
    passwordBytes.fill(0);
    if (rawKeyBytes) rawKeyBytes.fill(0);
    if (mixedKey && mixedKey !== rawKeyBytes) mixedKey.fill(0);
    if (keyfileHash) keyfileHash.fill(0);
}
SEC-HIGH-07 Unbounded chunkCache Violating RAM Bound & Buffer Aliasing Defect
High · CVSS 6.0 Remediated
Affected Files: app.js:2407, js/stream-unpacker.js:1048-1076 CWE: CWE-770 (Allocation of Resources Without Limits)

The Vault Explorer cache stored unlimited 4 MB plaintext chunks in an unbounded Map. Furthermore, blindly zeroizing evicted chunks in-place during extraction caused buffer aliasing corruption when extracting multi-chunk files (>16 MB). A dual-lifecycle policy was implemented: eviction safely drops references, while .fill(0) zeroization is strictly performed on vault session lock.

16 MB LRU Cache with Dual-Lifecycle Zeroization (`app.js`) 
chunkCache: {
    _map: new Map(),
    _maxChunks: 4, // Max 16 MB plaintext RAM cap
    set(key, val) {
        if (this._map.has(key)) this._map.delete(key);
        else if (this._map.size >= this._maxChunks) {
            const oldestKey = this._map.keys().next().value;
            // Drop reference safely without in-place .fill(0) to avoid aliasing in multi-chunk extractions
            this._map.delete(oldestKey);
        }
        this._map.set(key, val);
        return this;
    },
    clear() {
        // Full cryptographic byte scrubbing strictly executed when session locks
        for (const chunk of this._map.values()) {
            if (chunk && typeof chunk.fill === 'function') chunk.fill(0);
        }
        this._map.clear();
    }
}

5. Cryptographic Protocol & Container Format (`ZV3\0`)

5.1 PBKDF2-HMAC-SHA512 Key Derivation

ZevSafe derives its 256-bit AES master key using 600,000 iterations of PBKDF2-HMAC-SHA512 over a 32-byte (256-bit) cryptographically secure random salt generated via crypto.getRandomValues. This significantly exceeds the OWASP recommended floor of 210,000 rounds for HMAC-SHA512, providing resilient defense against GPU/ASIC parallel password cracking.

5.2 2FA Keyfile XOR Construction

When two-factor keyfile authentication is active, the final master key is derived as:

K_master = K_derived ⊕ SHA-256(KeyfileBytes)

Because the SHA-256 digest of keyfile bytes possesses cryptographic pseudorandomness, the XOR combination preserves uniform distribution across the 256-bit key space without entropy degradation.

5.3 12-Byte IV Construction & Collision Resistance

Each 4 MB chunk is encrypted under an explicitly structured 12-byte initialization vector (IV):

Offset 0..6   (7 bytes): CSPRNG Base IV Prefix (Unique per vault)
Offset 7..10  (4 bytes): Big-Endian Uint32 Monotonic Chunk Counter (0, 1, 2, ...)
Offset 11     (1 byte) : Final Chunk Indicator Flag (0x00 = intermediate, 0x01 = isLast)

This layout mathematically guarantees that no IV can ever collide within the same vault across up to $2^{32}-1$ chunks (16 Petabytes). Across multiple vaults using the same password, the 7-byte CSPRNG prefix provides a $2^{56}$ nonce collision bound, rendering collisions statistically impossible in practice.

5.4 42-Byte Chunk Associated Authenticated Data (AAD)

Every chunk's 128-bit GHASH authentication tag binds the following 42 bytes of AAD:

AAD = Magic(4B 'ZV3\0') ‖ Version(1B 0x03) ‖ Salt(32B) ‖ ChunkIndex(4B BE) ‖ isLast(1B)

This ensures that chunk reordering, chunk deletion, chunk substitution from another vault, and premature truncation attacks strictly cause AES-GCM tag verification to fail closed.
