Forensic Media Camouflage: Disguising Vaults Inside JPEGs & PNGs

How bicontextual polyglot steganography conceals encrypted ZV3 archives within standard media files, rendering vaults invisible to automated file filters.

1. What is a Polyglot File?

In computer science, a polyglot is a file that is simultaneously valid in two completely different format specifications.

In many jurisdictions or enterprise networks, carrying or uploading a file with an extension like .zsafe, .zev, .kdbx, or .tc instantly triggers red flags on endpoint monitoring software, firewall deep packet inspection (DPI), or automated cloud scanners.

🛡️ The Camouflage Invariant

ZevSafe's Polyglot Media Camouflage merges a valid JPEG or PNG image with an encrypted ZV3\0 STREAM AEAD vault. Double-clicking the file in Windows Explorer, macOS Finder, or Android Gallery opens a real, sharp picture. Dropping the exact same file into ZevSafe opens the encrypted vault!

2. JPEG & PNG Termination Markers (FF D9 & IEND)

How can two different software programs interpret the same file differently without corrupting each other? The secret lies in standard image format specifications:

Binary Layout · Polyglot Wire Format
[ 0x00000000 .. 0x0004A200 ]: Genuine JPEG Image (SOI 0xFFD8 ... EOI 0xFFD9)
                              -- Standard Image Viewers Stop Reading Here --
[ 0x0004A201 .. 0x0004A204 ]: ZV3 Magic Identifier ("ZV3\0" = 0x5A 0x56 0x33 0x00)
[ 0x0004A205 .. 0x0004A239 ]: 57-Byte ZV3 Header
[ 0x0004A23A .. EOF        ]: 4MB STREAM AEAD Ciphertext Chunks & Tail Manifest
  • JPEG (ISO/IEC 10918-1): A JPEG parser reads from the Start of Image marker (FF D8) until it hits the End of Image marker (FF D9). Everything after FF D9 is treated as benign trailing padding and ignored by graphics viewers.
  • PNG (ISO/IEC 15948): A PNG parser reads chunk by chunk until it encounters the IEND chunk (49 45 4E 44) followed by its 4-byte CRC. Bytes after the IEND marker are ignored by standard decoders.

3. The Sliding-Window ZV3 Container Detector

When a user drops an image file into ZevSafe's Unlock zone, ZevSafe doesn't just check byte offset 0. Instead, it activates the Sliding Window Detector:

  1. Scans the initial slice of the file looking for either the JPEG termination sequence [0xFF, 0xD9] or the PNG IEND chunk.
  2. Directly inspects the following 4 bytes for the magic identifier ZV3\0 (0x5A, 0x56, 0x33, 0x00).
  3. If the magic identifier is detected at offset $K$, the container parser offsets all future chunk and manifest reads by $K$ bytes.
  4. Decryption proceeds with identical bit-for-bit cryptographic precision.

4. The Bicontextual User Experience

When generating a camouflaged vault in ZevSafe:

  • Toggle the Max Security Options pill on the Lock screen.
  • Enable Polyglot Media Camouflage.
  • Drop an innocent cover photo (e.g. a high-resolution landscape photo from your camera roll) into the cover drop box.
  • Click Encrypt & Download. The output file is named Vacation_Landscape.jpg.
  • Open it in any standard photo app — it renders the cover image without any error messages.

5. Operational Tradecraft: Choosing Believable Covers

To avoid statistical suspicion:

  • File Size Proportionality: Do not hide a 4 GB vault behind a 50 KB icon thumbnail — an investigator might wonder why an icon is 4 GB. Instead, use an 8K drone video or high-bitrate raw photo album cover.
  • Preserve Image Aspect Ratio: Use real, authentic cover photos rather than synthetic test patterns to ensure metadata matches camera models.
