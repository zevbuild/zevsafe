1. What is ZevSafe? (Architecture & Core Philosophy)

ZevSafe is a 100% client-side, zero-knowledge, offline-first cryptographic security application designed to lock full folders, loose files, high-resolution media, and sensitive documents into impenetrable vaults.

Unlike traditional cloud storage platforms (Dropbox, Google Drive, OneDrive) or online encryption utilities that require you to upload data to external servers, ZevSafe is built on a strict operational premise:

🛡️ The Core Philosophy: "Trust No One. Not Even Us."

Zero Servers. Zero Telemetry. Zero Analytics. Zero Network Calls.
Every single cryptographic operation—compression, key derivation, chunk hashing, and Galois/Counter Mode authenticated encryption—happens exclusively on your local device CPU inside your web browser or installable Progressive Web App (PWA).

You can disconnect your Wi-Fi, turn on Airplane Mode, or run ZevSafe in an air-gapped forensic workstation with no internet access. The application will continue to encrypt and decrypt multi-gigabyte vaults seamlessly.

Why ZevSafe Outperforms Traditional Encryption Tools:

  • No Software Installation Required: Runs in modern Chromium, Firefox, and Safari browsers via standard W3C Web Cryptography APIs (window.crypto.subtle).
  • Installable Progressive Web App (PWA): Can be installed directly to your desktop or mobile home screen with one tap for instant, offline launch.
  • Zero Memory Leaks & Bounded Heap: Streams gigabytes of data in 4 MB chunks with an elastic background Web Worker pool (js/worker-bridge.js), keeping RAM consumption bounded below 150 MB across 5 GB+ files.
  • Instant In-Memory Vault Explorer: Browse directories, stream high-bitrate video, view high-resolution photo galleries, and edit documents in-browser without extracting unencrypted files to your hard drive.

2. What is a .zsafe File? (Binary Structure & Cryptography)

A .zsafe file (e.g., Financial_Archive_2026.zsafe) is an authenticated cryptographic container format engineered under the ZV3\0 STREAM AEAD specification.

Standard compression archives (like plain .zip or .tar) store directory trees with visible filenames, modified timestamps, and directory structures even when encrypted with weak ZipCrypto or basic AES-CBC. In contrast, a .zsafe file obfuscates all metadata and protects data integrity through authenticated encryption.

📦 The Anatomy of a .zsafe File

Every .zsafe container consists of three distinct mathematical regions:

  1. 57-Byte Container Header: Identifies the schema version (ZV3\0), active flags (Keyfile 2FA, Argon2id KDF), 4 MB chunk size, 32-byte CSPRNG salt, 7-byte Base IV prefix, and the byte offset of the encrypted catalog.
  2. STREAM AEAD Ciphertext Chunks: 4 MB blocks of payload data encrypted with AES-256-GCM. Each chunk is cryptographically bound to 42 bytes of Associated Authenticated Data (AAD) containing its sequence index and container salt.
  3. Encrypted Tail Manifest: A sealed JSON catalog at the end of the file containing relative paths, original filenames, byte sizes, and timestamps, decrypted in under 300 ms.
Binary Specification · 57-Byte Container Header
Offset (B) | Size | Encoding  | Field Name      | Cryptographic Purpose
-----------+------+-----------+-----------------+---------------------------------------------
0 .. 3     | 4 B  | ASCII     | MAGIC           | Constant: "ZV3\0" (0x5A 0x56 0x33 0x00)
4          | 1 B  | Uint8     | VERSION         | Schema revision: 0x03
5          | 1 B  | Uint8     | FLAGS           | Bit 0: Keyfile 2FA; Bit 1: Duress; Bit 2: Argon2id
6 .. 9     | 4 B  | Uint32 BE | CHUNK_SIZE      | Stream chunk size: 4,194,304 bytes (4 MB)
10 .. 41   | 32 B | Raw Bytes | SALT            | 256-bit CSPRNG salt for PBKDF2 / Argon2id
42 .. 48   | 7 B  | Raw Bytes | BASE_IV_PREFIX  | 7-byte CSPRNG prefix for chunk nonce mixing
49 .. 56   | 8 B  | Uint64 BE | MANIFEST_OFFSET | Big-endian byte offset of encrypted catalog

100% Backward Compatibility with Legacy .zev Files

ZevSafe was previously identified by the .zev file extension. To provide a unique, globally distinct ecosystem identity, the container extension was upgraded to .zsafe. All existing .zev and .zevsafe archives created in previous versions continue to be recognized, decrypted, played, and re-encrypted with 100% bit-for-bit backward compatibility.

3. How to Encrypt Files and Folders with ZevSafe

Locking private files into a .zsafe vault takes less than 30 seconds. Follow these 5 clear steps:

Step 1

Select Files or Folder

Open zevsafe.pages.dev. Click 📁 Browse Folder to select an entire folder structure (preserving all subfolders and files), or click 📄 Browse Files to select multiple loose documents or photos. You can also drag and drop your data directly onto the drop zone.

Step 2

Set Master Passphrase

Enter your master passphrase. The live entropy meter calculates your password strength in real time. For ultimate security, click the ⚡ Generate button to generate a 6-word CSPRNG Diceware passphrase with over 77 bits of cryptographic entropy.

Step 3

Configure Keyfile 2FA (Optional)

To protect your vault even if your password is leaked, expand the 🔑 Use Keyfile (Optional 2nd Factor) section. Click Select Keyfile to bind any local file (e.g. a family photo or document) as a mandatory second factor, or click ⚡ Generate 512-bit Keyfile.

Step 4

Generate Recovery Sheet

Click ⬇️ Download Sheet or 🖨️ Print Sheet to create an offline, physical cold-storage recovery sheet. This sheet records your 32-byte salt fingerprint and an optical QR code so you can restore your vault parameters offline.

Final Step: Encrypt & Download

Click 🔒 Encrypt & Download. The real-time progress tracker displays compression, chunk encryption, and manifest serialization. Your browser automatically downloads your sealed container as <foldername>.zsafe.

4. How to Decrypt and Explore a .zsafe Vault

Unlocking a .zsafe file requires no third-party software, decompression utilities, or command-line scripts:

  1. Load the Vault: Open ZevSafe and switch to the Unlock a Vault panel. Drag and drop your .zsafe (or legacy .zev) file into the decrypt drop zone, or click 📦 Select .zsafe File.
  2. Enter Credentials: Provide your master passphrase. If you configured a keyfile during encryption, attach it under the keyfile row.
  3. Optional 1-Scan QR Auto-Unlock: If you printed an optical Paper-Safe recovery sheet, click the 📷 Scan Paper QR button. ZevSafe's dual-engine scanner recognizes your credentials and initiates decryption automatically.
  4. Click Unlock Vault: ZevSafe validates the 57-byte header, derives the 256-bit AES master key, and decrypts the tail manifest in under 300 ms.
📂 In-Memory Web Vault Explorer Features

Once unlocked, ZevSafe launches the Decrypted Vault Explorer directly in browser RAM:

  • Cinema Video & Floating Audio: Click ▶️ Play on any video or audio file. ZevSafe streams high-bitrate media on-demand without loading the full video into memory.
  • Photo Lightbox: Click any photo to open the cinema lightbox with 1-click zoom, rotation, and slideshow navigation.
  • Live Document Editor: View code and text files with syntax line numbers and edit documents in-memory. Click 🔒 Re-Encrypt (.zsafe) to save edits directly back into a sealed vault!
  • Individual or Bulk Export: Download single files or click Download Decrypted ZIP to extract the complete unencrypted directory.
  • Lock Session: When you finish, click 🔒 Lock Session to immediately scrub all encryption keys and zero out plaintext buffers from memory.

5. Advanced Security Tiers, Keyfile 2FA & QR Cold Storage

ZevSafe provides defense-in-depth capabilities engineered for high-threat environments:

  • Configurable KDF Work Factors:
    • Standard Security (600,000 PBKDF2 Rounds): Pre-selected by default for instantaneous ~0.2s encryption with 6× the OWASP benchmark.
    • Hardened Security (1,200,000 Rounds): Recommended for multi-year cold storage archives.
    • Maximum Security (2,400,000 Rounds): 24× baseline resistance against state-sponsored parallel GPU/ASIC clusters.
    • Ultra Security (Argon2id Memory-Hard KDF): Allocates 64 MB of physical memory with $t=3, p=4$ per RFC 9106, rendering GPU brute-force economically impossible.
  • Forensic Polyglot Camouflage: Conceal your .zsafe vault behind a genuine JPEG image or MP4 file. Photo viewers display a real photo, while ZevSafe unlocks the hidden vault.
  • Duress Decoy Mode: Set an alternate duress password that unlocks an innocent decoy folder (e.g. recipes, travel photos) if forced to disclose credentials under coercion.

6. Golden Rules for Zero-Knowledge Vault Sovereignty

  • Passphrase Sovereignty: Because ZevSafe operates with true zero-knowledge, there is no password reset link, cloud recovery, or administrative backdoor. If you lose your password and keyfile, your data is mathematically unrecoverable.
  • Physical Paper-Safe Backup: Always print or handwrite your Diceware passphrase and salt fingerprint on a paper emergency sheet and store it in a fireproof safe.
  • Safe Storage on Any Cloud: Because AES-256-GCM is mathematically uncrackable when paired with strong passphrases, you can safely store your .zsafe files on Google Drive, Dropbox, USB flash drives, or external SSDs without cloud providers reading your data.
