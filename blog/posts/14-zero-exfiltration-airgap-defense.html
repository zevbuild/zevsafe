Zero-Exfiltration Air-Gap Defense-in-Depth

How strict Content Security Policy directives, complete font decoupling, and semantic credential binding turn the browser into an impenetrable offline cryptographic sandbox.

1. The Threat of Covert Network Exfiltration

In client-side web cryptography, robust algorithms (like AES-256-GCM) are useless if an attacker can smuggle user passphrases or decrypted plaintexts out of the browser.

Common exfiltration vectors include:

  • Cross-Site Scripting (XSS): Malicious scripts sending keys via fetch() or navigator.sendBeacon() to external logging endpoints.
  • DNS Pre-fetching & Font Leaks: Triggering dynamic font queries where font names encode private user tokens.
  • Clickjacking / Iframe Occlusion: Embedding the vault within an invisible parent frame to intercept keystrokes.

2. Strict Content-Security-Policy (CSP) Directives

Every page in ZevSafe embeds a strict, zero-exfiltration Content Security Policy across both HTML meta tags and HTTP response headers (_headers):

Content Security Policy · Strict Air-Gap Invariant
Content-Security-Policy: 
    default-src 'self'; 
    script-src 'self' 'unsafe-inline'; 
    style-src 'self' 'unsafe-inline'; 
    font-src 'self' data:; 
    img-src 'self' data: blob:; 
    media-src 'self' blob:; 
    frame-src 'self' blob:; 
    connect-src 'self' blob: data:; 
    object-src 'none'; 
    base-uri 'self';
    frame-ancestors 'none';
🛡️ Why connect-src 'self' Matters

By locking connect-src 'self' blob: data:, the browser engine physically blocks any outbound HTTP, WebSocket, WebRTC, or Beacon request to any external server. Even if untrusted third-party code were somehow injected, it is mathematically blocked by the browser kernel from exfiltrating bytes!

3. The Google Font Decoupling Invariant

In Phase 13 of ZevSafe's engineering roadmap, all external font CDNs (including fonts.googleapis.com and fonts.gstatic.com) were permanently purged:

  • Zero Network Pings: Visiting ZevSafe emits 0 network queries to Google or any other font provider.
  • Zero Layout Shift (CLS 0.00): Native system fonts (such as Inter, Outfit, and JetBrains Mono) render instantly on the initial paint, eliminating the visual jumping common with web fonts.
  • Strict Air-Gap Compliance: The web app remains 100% styled and perfectly readable on air-gapped computers disconnected from the global internet.

4. Native W3C Credential Management API Integration

Many users rely on trusted browser password managers (Chrome Password Manager, Bitwarden, 1Password, Dashlane, Apple Keychain). However, web apps without traditional backend login forms often fail to trigger browser password saving prompts.

ZevSafe bridges this gap using standard W3C navigator.credentials:

JavaScript Architecture · W3C Credential Management
// Bind active vault name to username and store in local password manager
async function saveVaultCredential(vaultIdentifier, masterPassword) {
    if (window.PasswordCredential && navigator.credentials?.store) {
        try {
            const cred = new PasswordCredential({
                id: vaultIdentifier, // e.g. "Financial_Archive.zev"
                password: masterPassword,
                name: `ZevSafe Vault: ${vaultIdentifier}`
            });
            await navigator.credentials.store(cred);
        } catch (e) {
            // Graceful fallback for non-supporting browsers
        }
    }
}

This ensures that your vault passwords remain securely saved inside your hardware-backed keychain without requiring third-party cloud extensions.
